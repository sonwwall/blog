# 第三节：存储器分级：SSD，内存和L1 Cache相比速度差多少倍

## 1. 存储器为什么要分级

CPU 的计算速度很快，但不同存储介质的速度差距非常大。

如果 CPU 每次都直接去内存甚至 `SSD` 里取数据，那么大量时间都会浪费在等待上。

所以计算机里会做存储器分级，常见顺序是：

- 寄存器
- `L1 Cache`
- `L2 Cache`
- `L3 Cache`
- 内存
- 硬盘 / `SSD`

整体规律就是：

- 越靠近 CPU，速度越快，容量越小，价格越高
- 越远离 CPU，速度越慢，容量越大，价格越低

## 2. 各级存储器的大致速度

### 2.1 寄存器

寄存器离 CPU 核心最近，速度最快。

- 读写大致在半个到一个 CPU 周期左右

### 2.2 `L1 Cache`

`L1 Cache` 比寄存器更远一点，但还是非常快。

- 通常大小在几十 `KB` 到几百 `KB`
- 读写速度大约在 `2~4` 个 CPU 周期

### 2.3 `L2 Cache`

`L2 Cache` 比 `L1 Cache` 更大，也更慢。

- 大小通常比 `L1 Cache` 大很多
- 有的可能在几百 `KB` 到几 `MB`
- 访问速度大约在 `10~20` 个 CPU 周期

### 2.4 `L3 Cache`

`L3 Cache` 比 `L2 Cache` 更大，也更慢。

- 大小通常比 `L2 Cache` 更大
- 访问速度大约在 `20~60` 个 CPU 周期

### 2.5 内存

内存和 CPU 已经有一段距离了，需要通过总线连接。

- 主要材料是半导体硅
- 访问速度通常在 `200~300` 个 CPU 周期左右

### 2.6 硬盘 / `SSD`

`SSD` 仍然比内存慢很多。

- 内存通常比 `SSD` 快 `10~1000` 倍

## 3. SSD、内存和 L1 Cache 相比速度差多少倍

这个问题一般记范围就够了。

- 内存比 `SSD` 快大约 `10~1000` 倍
- `L1 Cache` 比内存快大约 `100` 倍左右

所以合起来可以近似记成：

- `L1 Cache` 比 `SSD` 快大约 `1000~100000` 倍

这里写成范围更合适，因为不同机器、不同负载、不同测试方法差别都会很大。

## 4. CPU 取数据时的查询顺序

如果 CPU 要的数据不在寄存器里，就会继续往下找。

常见顺序是：

1. 先查 `L1 Cache`
2. `L1` 没有，再查 `L2 Cache`
3. `L2` 没有，再查 `L3 Cache`
4. `L3` 还没有，最后去内存里取

也就是图片里的流程：

`L1 -> L2 -> L3 -> 内存`

## 5. 什么是缓存命中率

命中率就是：

- 在缓存中找到了想要的数据

找不到就叫：

- 未命中
- `miss`

常见说法是：

- `L1` 的命中率可能在 `80%` 左右
- `L1 + L2 + L3` 加起来，整体命中率可能能到 `95%` 左右

这也是缓存系统存在的意义：尽量把大多数访问拦截在更快的层级里，不要每次都跑去内存。

## 6. 为什么不能每次都直接从内存取指令

如果 CPU 每执行一条指令，都先去内存里一条条读取，再回来执行，那么代价太大了。

因为一次内存访问可能就要 `200~300` 个 CPU 周期。

这样 CPU 大部分时间都在等数据，不是在计算。

所以程序真正运行时，会尽量让热点指令和热点数据留在缓存里。

## 7. 为什么 L1 要分成指令缓存和数据缓存

`L1 Cache` 通常会拆成两个区域：

- 指令缓存
- 数据缓存

这样做的原因是：

- CPU 取指令和取数据都非常频繁
- 如果混在一起，更容易互相覆盖
- 一旦数据把指令区域冲掉，性能影响会非常明显

所以 `L1` 一般会做分离。

而 `L2`、`L3` 通常不需要像 `L1` 这样严格拆分成指令区和数据区，它们更多是作为更大一级的统一缓存来用。

## 8. 缓存中的数据结构

可以先把内存想成一张只有一列的大表，每个地址对应一个位置。

缓存可以理解成一张多列的表，这张表里的每一行就是一个缓存条目。

缓存条目里通常不会只放“数据”本身，还会带一些额外信息，比如：

- 这一行缓存对应的是哪段内存
- 这一行里的数据内容
- 状态位

所以缓存不是简单“把内存直接复制一遍”，而是把一部分热点内容按条目组织起来。

## 9. 内存地址如何映射到缓存条目

缓存条目数量远小于内存地址数量，所以必须有映射方法。

例如：

- 有 `1000` 个内存地址，编号是 `0~999`
- 但缓存只有 `10` 个条目，编号是 `0~9`

那么就需要一个规则，把很多内存地址映射到有限个缓存条目上。

一个很直观的例子就是取模：

- 地址 `701`
- `701 % 10 = 1`
- 那就把它映射到缓存条目 `1`

当然，真实 CPU 缓存实现要比这个复杂，会涉及组相联、标记位这些内容，但先这么理解就够用了。

## 10. 二维数组为什么更适合逐行遍历

如果有一个二维数组，总共有很多元素，通常更适合逐行遍历，而不是逐列遍历。

原因是大多数语言里，二维数组在内存中通常按行连续存放。

逐行遍历时：

- 访问的是相邻内存
- 更容易命中缓存
- 预取也更有效

逐列遍历时：

- 每次访问跨得很远
- 更容易造成缓存未命中
- 性能通常更差

所以在这种情况下：

- 逐行遍历通常比逐列遍历更快

## 11. 这一节先记住的点

- 存储器分级顺序一般是：寄存器、`L1`、`L2`、`L3`、内存、`SSD`
- 越靠近 CPU 越快，越远越慢
- `L1` 大约 `2~4` 周期，`L2` 大约 `10~20` 周期，`L3` 大约 `20~60` 周期，内存大约 `200~300` 周期
- CPU 取数据一般按 `L1 -> L2 -> L3 -> 内存` 的顺序查找
- `L1` 通常分指令缓存和数据缓存
- 命中率越高，程序通常越快
- 二维数组通常逐行遍历更容易命中缓存
