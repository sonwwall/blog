# 第九节：高级技巧之日志分析：利用Linux指令分析Web日志

日志分析是 Linux 运维和排障里非常实用的一类能力。

很多时候，我们并不需要先把日志导入专门的平台，直接借助 Linux 自带的文本处理命令，就能快速看出一个网站的大致访问情况。

这一节主要围绕 6 个步骤展开：

1. 先判断日志是否适合拉取和离线分析
2. 先用 `less` 观察日志整体结构
3. 分析 PV
4. 对 PV 进行分组统计
5. 分析 UV
6. 对 UV 进行分组统计

## 1. 什么是 Web 日志分析

这里讨论的对象，通常是 Web 服务器的访问日志，比如 `nginx` 的 `access.log`。

一条访问日志里，往往会包含这些信息：

- 访问者 IP
- 访问时间
- 请求方法和请求路径
- 返回状态码
- User-Agent 等附加信息

通过这些字段，我们可以快速统计出：

- 网站一共被访问了多少次
- 每天访问量大概是多少
- 有多少独立访客
- 某一天有哪些 IP 访问过网站

这类分析的核心思路其实很简单：

**先把日志当成文本，再把每一列当成结构化字段去提取、排序、去重、计数。**

## 2. 第一步：先判断能否把日志拉下来分析

在正式分析之前，先不要急着直接下载大日志文件。

应先判断两个问题：

- 日志文件有多大
- 本机和服务器的 CPU、内存、磁盘空间是否足够

因为日志分析本质上是数据处理。

如果日志很大，例如已经达到几个 GB 甚至更高，那么：

- 下载会耗费时间
- 排序和去重会消耗较多内存与 CPU
- 本机空间不够时还可能影响正常工作

所以第一步不是“立刻分析”，而是先评估资源是否允许这样做。

## 3. 第二步：先用 `less` 看懂日志格式

在动手统计之前，要先确认日志每一列分别是什么。

最直接的方法就是：

```bash
less access.log
```

这样做的目的不是统计，而是观察。

需要重点看清：

- 第 1 列是不是客户端 IP
- 第 4 列是不是时间字段
- 请求行、状态码分别在第几列

在很多常见的 `nginx access.log` 格式里：

- `$1` 往往可以看作客户端 IP
- `$4` 往往是时间字段，例如 `[01/Jun/2015:00:00:01`

后面很多 `awk` 命令，都是建立在这个前提上的。  
如果你的日志格式不同，字段位置也要跟着调整。

## 4. 第三步：分析 PV

PV 可以理解为页面访问量，或者更宽泛一点，理解成“请求次数”。

如果一行日志代表一次请求，那么统计 PV 最直接的方法就是统计行数。  
当然，在一些讲解材料里，也会先把时间字段抽出来观察访问记录分布。

例如可以先提取第 4 列：

```bash
awk '{print $4}' access.log | less
```

这个命令的作用是：

- 用 `awk` 读取日志
- 取出每一行的第 4 列
- 再交给 `less` 浏览

这样可以快速验证：

- 第 4 列确实是不是时间
- 时间字段的格式是否统一

如果只是想知道总 PV，通常可以直接统计总行数：

```bash
wc -l access.log
```

因为在 access 日志里，一行通常就代表一次访问请求。

## 5. 第四步：PV 分组统计

当我们已经确认第 4 列是时间后，就可以进一步按日期分组，看看每天的 PV。

图片里的做法是从第 4 列里截取日期部分：

```bash
awk '{print substr($4, 2, 11)}' access.log | sort | uniq -c
```

这个命令可以拆成 3 步理解：

### 5.1 `substr($4, 2, 11)` 在做什么

很多日志时间字段长这样：

```text
[01/Jun/2015:00:00:01
```

这里：

- 第 1 个字符是 `[`，不需要
- 前 11 个有效字符正好是日期部分 `01/Jun/2015`

所以：

```bash
substr($4, 2, 11)
```

表示：

- 从第 4 列开始取值
- 从第 2 个字符开始截取
- 一共截取 11 个字符

最终得到纯日期，例如：

```text
01/Jun/2015
02/Jun/2015
03/Jun/2015
```

### 5.2 为什么要接 `sort`

`uniq` 只能统计相邻重复行。

所以在 `uniq -c` 之前，一般都要先排序：

```bash
sort
```

这样相同日期就会排在一起，后面的 `uniq -c` 才能正确计数。

### 5.3 命令结果说明什么

最后输出的结果类似这样：

```text
2837 01/Jun/2015
2864 02/Jun/2015
2825 03/Jun/2015
896  04/Jun/2015
```

它表示：

- `01/Jun/2015` 这一天有 `2837` 次访问
- `02/Jun/2015` 这一天有 `2864` 次访问
- `03/Jun/2015` 这一天有 `2825` 次访问

所以这一步本质上就是：

**按日期对 PV 进行分组统计。**

## 6. 第五步：分析 UV

UV 指的是独立访客数。  
在简单分析里，常常会用“不同 IP 的数量”近似表示 UV。

这里要注意：

**IP 数量并不一定等于真实用户数，但在基础练习和初步分析中，经常这样近似处理。**

如果第 1 列是访问者 IP，那么统计 UV 的一个常见命令是：

```bash
awk '{print $1}' access.log | sort | uniq | wc -l
```

这个命令的逻辑是：

- 先取出所有 IP
- 再排序
- 然后去重
- 最后统计去重后的行数

比如结果是：

```text
2660
```

就说明这个日志样本中，大约有 `2660` 个不同 IP，也就是近似 `2660` 个 UV。

## 7. 第六步：分组分析 UV

只知道总 UV 还不够。  
很多时候我们还想知道：

- 每天有多少独立访客
- 某一天的访问用户数是升了还是降了

图片里给出的思路，是先把“日期 + IP”拼在一起，再去重，再按日期聚合。

脚本核心逻辑可以整理成下面这样：

```bash
awk '{print substr($4,2,11) " " $1}' access.log | \
sort | uniq | \
awk '{uv[$1]++} END {for (day in uv) print day, uv[day]}'
```

这段命令可以这样理解：

### 7.1 先拼出“日期 + IP”

```bash
awk '{print substr($4,2,11) " " $1}' access.log
```

输出结果会类似：

```text
01/Jun/2015 192.168.1.10
01/Jun/2015 192.168.1.12
01/Jun/2015 192.168.1.10
02/Jun/2015 192.168.1.15
```

这一步表示：

- 取出日期
- 再取出 IP
- 组合成一行

### 7.2 对“日期 + IP”去重

后面接上：

```bash
sort | uniq
```

它的含义是：

- 同一天内，同一个 IP 多次访问，只保留一条
- 不同天的同一个 IP，会被视为不同记录

这正符合“按天统计 UV”的需求。

### 7.3 再按日期累加

最后这段：

```bash
awk '{uv[$1]++} END {for (day in uv) print day, uv[day]}'
```

含义是：

- `$1` 现在是日期
- `uv[$1]++` 表示该日期对应的 UV 数加 1
- `END` 中再把所有日期的结果输出出来

最终就可以得到每一天的 UV，例如：

```text
22/May/2015 254
26/May/2015 218
03/Jun/2015 263
```

这表示：

- `22/May/2015` 这一天有 `254` 个独立 IP
- `26/May/2015` 这一天有 `218` 个独立 IP
- `03/Jun/2015` 这一天有 `263` 个独立 IP

## 8. 这一组命令为什么重要

这节内容表面上是在做日志统计，实际上是在综合训练多个 Linux 基础能力：

- `less` 用来浏览大文件
- `awk` 用来提取字段和做简单统计
- `sort` 用来排序
- `uniq` 用来去重和计数
- `wc` 用来汇总数量

也就是说，这不是单一知识点，而是把前面学过的多个命令串起来，在真实场景里一起使用。

## 9. 总结

这一节可以记住 3 个重点：

- Web 日志分析，本质上是在对文本日志做结构化处理
- `awk` 是这类分析里非常高频、非常核心的工具
- 通过 PV 和 UV 的统计，可以快速了解一个网站的大致访问情况

如果只记最终思路，可以压缩成下面几句：

- 看总访问量：统计日志总行数
- 看每日 PV：提取日期后排序、分组计数
- 看总 UV：提取 IP 后去重计数
- 看每日 UV：把“日期 + IP”组合后去重，再按日期聚合
