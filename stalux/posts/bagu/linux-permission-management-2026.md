# 第六节：用户和权限管理指令：请简述Linux权限划分的原则

这一节主要围绕 4 个点展开：

1. Linux 如何抽象用户、组和权限
2. 文件权限字符串怎么理解
3. Linux 权限划分遵循什么原则
4. 常见的用户和权限管理命令有哪些

## 1. 用户、组和权限的基本抽象

Linux 会把系统中的操作者抽象成**用户**和**组**。

- **用户**：一个可以登录系统、发起操作的账户
- **组**：多个用户的集合，可以统一分配某类权限
- **root**：超级管理员账户，拥有极高权限

这样设计的目的，是让系统能针对不同身份分配不同权限，而不是让所有人共享同一套能力。

### 1.1 为什么要有组

如果每个文件都给每个用户单独授权，管理成本会非常高。  
所以 Linux 引入了组：

- 把职责相近的用户放进同一个组
- 把资源权限授权给组
- 新用户加入组后，就自动获得对应权限

这就是“按角色管理权限”的思想。

## 2. 文件权限的表示方式

执行 `ls -l` 时，常见到类似下面的结果：

```bash
-rwxr-xr-x 1 root root 142144 Sep 5 2019 /usr/bin/ls
```

最前面的 10 个字符可以这样理解：

```text
- rwx r-x r-x
```

其中：

- 第 1 位表示文件类型
- 第 2 到 4 位表示**拥有者**权限
- 第 5 到 7 位表示**所属组**权限
- 第 8 到 10 位表示**其他用户**权限

### 2.1 第一位：文件类型

- `-`：普通文件
- `d`：目录

### 2.2 后九位：权限位

每 3 位是一组：

- `r`：读权限
- `w`：写权限
- `x`：执行权限
- `-`：没有该权限

例如：

- `rwx`：可读、可写、可执行
- `r-x`：可读、可执行，不可写
- `rw-`：可读、可写，不可执行

## 3. 文件和目录上的权限含义不同

虽然都是 `r`、`w`、`x`，但放在文件和目录上含义不同。

### 3.1 普通文件权限

- `r`：可以读取文件内容
- `w`：可以修改文件内容
- `x`：可以把文件当作程序执行

### 3.2 目录权限

- `r`：可以查看目录中的文件名列表
- `w`：可以在目录中创建、删除、重命名文件
- `x`：可以进入目录，并访问目录中的项目

所以目录权限经常比文件权限更容易考察。

### 3.3 一个常见问题

**如果一个目录只有读权限，那么这个目录下面的文件还能写吗？**

通常不能直接简单回答“能”或“不能”，要看目录本身有没有 `w` 和 `x`。

可以先记结论：

- 目录没有 `x`，通常连进入目录和访问里面文件都做不到
- 目录没有 `w`，通常不能在目录里创建、删除、改名
- 文件内容能否写入，还要同时看该文件自身权限以及目录访问权限

也就是说，**目录权限控制的是“对目录项的操作能力”，文件权限控制的是“对文件内容的操作能力”。**

## 4. Linux 权限划分的原则

这个问题是本节的重点。

### 4.1 最小权限原则

Linux 权限设计最核心的思想是：

**只给用户、程序完成工作所必需的最小权限。**

例如：

- 应用能用普通用户运行，就不要直接用 `root`
- 只需要读日志，就不要给写权限
- 只需要执行脚本，就不要给修改权限

这样做的好处是：

- 降低误操作风险
- 降低攻击面
- 某个程序被攻破时，影响范围更小

### 4.2 权限边界清晰

一个好的权限架构，不只是“能管住”，还应该做到：

- 权限划分足够清晰
- 不同用户、不同程序之间边界明确
- 权限分配和维护成本足够低

本质上就是：**谁能做什么，要定义清楚。**

### 4.3 相互牵制、相互隔离

在实际生产环境中，管理员权限往往不会集中在一个人或一个程序手里，而是会拆分、隔离、彼此制约。

例如：

- 不同角色负责不同资源
- 高权限操作要经过授权或审计
- 普通应用之间尽量互不影响

这背后的目标是：**保证系统安全和稳定。**

### 4.4 尽可能少用 root

图片里给出的一个典型例子是：

如果 MySQL 直接跑在 `root` 权限下，一旦 MySQL 被攻破，攻击者拿到的就不只是数据库权限，而可能是整台机器的高权限控制权。

所以实际部署里通常遵循：

- 尽可能少使用 `root`
- 服务进程尽量跑在专门的普通账户下
- 只在必要时临时提升权限

这也叫**权限包围**或**权限约束**思想。

### 4.5 系统层面的分级保护

除了文件系统权限，操作系统本身也有更底层的权限分级思想。

例如 CPU 权限环：

- `Ring 0`：内核态，权限最高
- `Ring 3`：用户态，权限最低

可以把它理解成：

- 内核负责最核心能力
- 普通应用运行在低权限环境中
- 应用如果想访问硬件或关键系统资源，通常需要通过系统调用进入内核

这说明 Linux 的权限管理不是单点设计，而是从系统层面做分级保护。

## 5. 用户和分组查看命令

### 5.1 查看当前属于哪些组

```bash
groups
```

这个命令会列出当前用户所属的所有组。

例如有些系统里常见：

- `adm`：和系统监控、部分日志访问相关
- `sudo`：允许用户通过 `sudo` 临时提升权限

### 5.2 查看用户 ID 和组 ID

```bash
id
```

常见输出中会包含：

- `uid`：用户 ID
- `gid`：主组 ID
- `groups`：该用户所属的所有组及组 ID

### 5.3 查看用户信息文件

```bash
cat /etc/passwd
```

`/etc/passwd` 中每一行通常类似：

```text
root:x:0:0:root:/root:/bin/bash
```

各字段含义可以这样理解：

1. 用户名
2. 密码占位符
3. `uid`
4. `gid`
5. 用户说明信息
6. 家目录
7. 登录 shell 路径

## 6. 常见用户管理命令

### 6.1 创建用户

```bash
sudo useradd foo
```

这表示创建一个名为 `foo` 的用户。

### 6.2 给用户添加次级分组

```bash
sudo usermod -a -G sudo foo
```

这里要注意：

- `-G`：指定次级分组列表
- `-a`：append，表示追加

如果少了 `-a`，就可能把用户原有的次级分组覆盖掉。

### 6.3 修改用户主组

```bash
sudo usermod -g somegroup foo
```

这个命令是把用户 `foo` 的**主要分组**改成 `somegroup`。

## 7. 常见权限管理命令

### 7.1 修改执行权限

```bash
chmod +x ./foo
chmod -x ./foo
chmod +rwx ./foo
```

含义分别是：

- 增加执行权限
- 去掉执行权限
- 同时增加读、写、执行权限

### 7.2 使用数字方式修改权限

权限还可以用数字表示：

- `r = 4`
- `w = 2`
- `x = 1`

因此：

- `7 = 4 + 2 + 1 = rwx`
- `6 = 4 + 2 = rw-`
- `5 = 4 + 1 = r-x`

例如：

```bash
chmod 777 ./foo
chmod 666 ./foo
```

可以分别理解为：

- `777`：`rwxrwxrwx`
- `666`：`rw-rw-rw-`

不过在实际环境中，`777` 一般过于宽松，不建议随意使用。

### 7.3 修改文件所属用户

```bash
chown bar ./foo
```

这表示把文件 `./foo` 的拥有者改成 `bar`。

## 8. 一个容易混淆的点：不可读但可执行

原始笔记里提到：

> 如果一个文件设置为不可读但是可以执行，那么不可以执行。

这个说法不够严谨，面试里最好这样回答：

- 对于 **脚本文件**，通常解释器需要读取内容，所以没有读权限往往无法正常执行
- 对于某些 **二进制可执行文件**，执行与读取并不是完全等价的概念，情况更复杂，不能简单一刀切

因此更稳妥的表达是：

**“脚本通常依赖读权限；可执行二进制文件是否能执行，不能只凭一句‘不可读就一定不能执行’来概括。”**

## 9. 小结

如果面试里问“请简述 Linux 权限划分的原则”，可以直接概括成下面几点：

1. Linux 按用户、组、其他用户来划分权限对象
2. 权限按读、写、执行三种能力拆分
3. 权限设计遵循最小权限原则
4. 尽量减少 `root` 的使用，高权限要拆分和隔离
5. 系统层面也通过用户态、内核态等方式做分级保护

如果只需要一句话总结，可以说：

> Linux 权限划分的原则，就是按不同身份分配不同的读、写、执行权限，并遵循最小权限、边界清晰、相互隔离和尽量少用 root 的思想来保证系统安全与稳定。
