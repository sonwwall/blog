# 第五节：进程，重定向和管道指令：xargs指令的作用是？

这一节主要讲 4 个点：

1. 什么是进程
2. 什么是标准输入流、标准输出流、标准错误流
3. 什么是重定向、匿名管道、命名管道
4. `xargs` 和 `tee` 在实际命令组合中的作用

## 1. 进程

应用的可执行文件是放在文件系统里的；当它被启动后，操作系统会在内存中形成一个运行中的副本，这个副本就是**进程**。

可以把进程理解成：**程序的一次执行实例**。

常见查看进程的命令：

```bash
ps -ef
```

常见字段包括：

- `UID`：启动用户
- `PID`：当前进程 ID
- `PPID`：父进程 ID
- `C`：CPU 占用相关信息
- `STIME`：启动时间
- `TTY`：关联终端
- `TIME`：累计占用 CPU 时间
- `CMD`：启动命令

也可以使用：

```bash
ps aux
```

## 2. 标准流

Linux 里，进程运行时通常会关联三种标准数据流：

- **标准输入流（stdin）**：可以作为进程执行的上下文，进程可以从输入流中获取数据
- **标准输出流（stdout）**：进程正常执行后的输出结果
- **标准错误流（stderr）**：进程执行过程中发生异常时输出的错误信息

后面的重定向、管道，本质上都是围绕这三种标准流在做连接和转发。

## 3. 重定向

重定向的本质是：**把原本输出到终端的数据，改为输出到文件；或者把原本从终端读取的数据，改为从文件读取。**

### 3.1 输出重定向

例如：

```bash
ls -l > out
cat out
```

这里的含义是：

- `ls -l` 的标准输出不再直接打印到屏幕
- 而是写入文件 `out`
- 再通过 `cat out` 查看文件内容

如果希望**追加**到文件末尾，而不是覆盖，可以使用：

```bash
start.sh >> /var/log/somelogfile
```

### 3.2 错误输出重定向

例如：

```bash
ls1 &> out
cat out
```

这里 `ls1` 是一个不存在的命令，报错信息会被写入 `out`。  
也就是说，`&>` 可以把标准输出和标准错误一起重定向到目标文件。

## 4. 管道

管道的作用是：**在命令和命令之间传递数据**。  
本质上是让一个进程的输出，成为另一个进程的输入。

### 4.1 匿名管道

最常见的就是 `|`。

例如：

```bash
find ./ -i "*.java" | wc -l
```

含义是：

- `find` 先把结果写入输出流
- `wc -l` 再从输入流中读取这些结果
- 最终统计出结果的行数

再比如筛选：

```bash
find ./ | grep Spring
find ./ | grep Spring | grep -v MyBatis
```

这说明匿名管道适合把多个命令串起来，逐步加工数据。

## 5. 命名管道

匿名管道只能临时连接一条命令链。  
如果我们希望“拿到一个真正存在于文件系统里的管道文件”，就可以使用**命名管道**。

命名管道使用 `mkfifo` 创建：

```bash
mkfifo pipe1
ls
```

创建后，`pipe1` 会作为一个特殊文件出现在文件系统中。  
它本质上仍然是管道，只是**利用文件系统把管道命名了**。

### 5.1 一个最简单的例子

先在一个终端中读取：

```bash
cat pipe1
```

再在另一个终端中写入：

```bash
echo "xxx" > pipe1
```

这时前一个终端就能读到：

```text
xxx
```

这说明命名管道可以让多个进程之间更方便地通信。

### 5.2 图片中的 Shell 程序在做什么

图片中的代码是：

```bash
mkfifo pipe1
mkfifo pipe2
echo -n run | cat - pipe1 > pipe2 &
cat < pipe2 > pipe1
```

它的核心作用是：**用两个命名管道把两个 `cat` 进程首尾连接起来，构造出一个可以循环传递数据的通信结构。**

可以这样理解：

1. `pipe1` 和 `pipe2` 是两个中转站
2. 后台命令 `echo -n run | cat - pipe1 > pipe2 &` 先把 `run` 写进去，然后继续等待从 `pipe1` 读数据，再统一写到 `pipe2`
3. 前台命令 `cat < pipe2 > pipe1` 会持续从 `pipe2` 读，再写回 `pipe1`
4. 于是数据会在 `pipe1` 和 `pipe2` 之间来回流动

这类写法通常不是业务里常见的正式写法，更重要的是用来说明：  
**命名管道可以把多个进程串成更复杂的通信拓扑，而不只是简单的一进一出。**

## 6. xargs 的作用

`xargs` 的核心作用可以概括为一句话：

> 从标准输入流中读取字符串，按空白符、换行符等切割，然后基于这些字符串构造并执行一条条命令。

也就是说，`xargs` 做了两件事：

1. 从输入流里拿到一批字符串
2. 按我们指定的模板，把这些字符串拼成命令再执行

因此它大大拓展了 Linux 命令组合的能力。

### 6.1 基本理解

可以把 `xargs` 看成一个“命令构造器”：

```bash
前一个命令的输出 | xargs 后一个命令
```

前一个命令负责产出数据，`xargs` 负责把这些数据组织成参数，交给后一个命令。

### 6.2 使用 `-I` 定义占位符

例如目录里有：

```text
x.a
y.a
z.a
```

如果想统一加上前缀，可以先看 `xargs` 生成的命令：

```bash
ls | xargs -I GG echo "mv GG prefix_GG"
```

输出会是：

```bash
mv x.a prefix_x.a
mv y.a prefix_y.a
mv z.a prefix_z.a
```

确认没问题后，把 `echo` 去掉，真正执行：

```bash
ls | xargs -I GG mv GG prefix_GG
```

执行完成后，文件名会变成：

```text
prefix_x.a
prefix_y.a
prefix_z.a
```

这里的重点是：

- `ls` 提供输入数据
- `xargs` 把每一项取出来
- `-I GG` 指定占位符是 `GG`
- `mv GG prefix_GG` 是要套用的命令模板

### 6.3 xargs 的典型使用场景

#### 场景一：把一批输入转换成命令参数

```bash
find ./ -name "*.java" | xargs grep Spring
```

含义是：先找到所有 `.java` 文件，再把这些文件路径作为参数交给 `grep Spring`。

#### 场景二：配合模板生成批量命令

```bash
ls | xargs -I {} echo "rm {}"
```

先预览要执行的命令，确认无误后再去掉 `echo`。

## 7. tee 指令

`tee` 的作用是：**一边把数据继续往后传，一边把数据写入文件。**

例如：

```bash
find ./ -i "*.java" | tee JavaList | grep Spring
```

它做了两件事：

1. 把 `find` 的结果写入文件 `JavaList`
2. 同时把这些结果继续传给后面的 `grep Spring`

所以 `tee` 常用于“既想保存中间结果，又不想打断管道”的场景。

## 8. 总结

这一节可以总结为三层：

- **进程**：程序启动后在内存中的运行副本
- **重定向**：控制标准输入、标准输出、标准错误流的去向
- **管道**：让多个进程之间传递数据

其中又要特别记住两类管道：

- **匿名管道**：用 `|` 串联命令，适合临时的一条命令链
- **命名管道**：用 `mkfifo` 创建真实存在的管道文件，适合让多个进程更灵活地通信

而 `xargs` 的价值在于：

- 它会从标准输入流中读取字符串
- 把字符串切割成一项项数据
- 再按我们需要的模板构造成命令执行

所以可以说，`xargs` 是连接“数据流”和“命令执行”的关键工具。
