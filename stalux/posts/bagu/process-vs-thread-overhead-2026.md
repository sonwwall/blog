# 第十四节：进程和线程：进程的开销比线程大在了哪里？

这一节主要围绕 6 个点展开：

1. 进程和线程分别是什么
2. 操作系统如何给大量进程和线程分配 CPU
3. 进程和线程常见有哪些状态
4. 操作系统内部如何描述进程和线程
5. 为什么进程之间要做隔离
6. 为什么创建和切换进程通常比线程更重

## 1. 什么是进程和线程

先记一个最常见的定义：

- **进程**：程序的一次执行实例，是资源分配的基本单位
- **线程**：进程内部的执行流，是 CPU 调度的基本单位

也可以换一种更直观的理解：

- 进程更像一个“运行中的应用”
- 线程更像这个应用内部真正干活的执行单元

线程常被叫作**轻量级进程**，原因不是它和进程完全一样，而是：

- 它也能被调度执行
- 但它通常不单独拥有完整资源集合
- 它更多是共享所属进程的大部分资源

因此常见规律是：

- 进程负责承载资源
- 线程负责消耗 CPU 执行代码

## 2. 操作系统怎么让这么多任务轮流执行

现实机器里，CPU 核心数量通常不多，但进程和线程数量往往很多。

所以绝大多数时候，不可能让每个任务一直独占一个 CPU 核心。  
操作系统通常会采用**分时技术**来安排执行。

### 2.1 什么是时间片

可以先记一个结论：

**每个可运行的进程或线程，都会在某个时刻拿到一个时间片。**

在这个时间片内，它可以占用 CPU 执行；时间片结束后，调度器可能会把 CPU 切给下一个任务。

因此我们平时看到的“很多程序同时运行”，很多时候并不是真正同一时刻都在执行，而是：

- 操作系统快速轮换
- 每个任务执行一小段时间
- 切换得足够快后，看起来像同时运行

### 2.2 并发和并行

这两个词很容易混。

- **并发**：一段时间内多个任务看起来都在推进，不要求一定多核
- **并行**：多个任务在同一时刻真正同时执行，通常要求多核

所以：

- 单核机器也可以并发
- 多核机器才更容易实现并行

## 3. 进程和线程有哪些状态

操作系统为了调度任务，通常会给进程或线程维护状态信息。

最常见的三种状态是：

- **运行态**：当前正在 CPU 上执行
- **就绪态**：已经具备执行条件，正在等 CPU
- **阻塞态**：暂时不能继续执行，正在等某个事件

### 3.1 运行态和就绪态如何切换

最典型的场景就是时间片轮转：

1. 某个任务正在运行
2. 它的时间片用完
3. 操作系统保存它的执行现场
4. 把它从运行态改成就绪态
5. 再挑选下一个就绪任务继续执行

这就是最基本的调度循环。

### 3.2 为什么会进入阻塞态

任务进入阻塞态，通常是因为它发起了某个暂时拿不到结果的请求，例如：

- 读磁盘
- 等网络数据
- 等输入输出完成

这时继续占着 CPU 也没意义，所以操作系统通常会让它先挂起，等结果回来再说。

### 3.3 阻塞态如何回到就绪态

常见过程可以理解成：

1. 任务发起 I/O 请求
2. 任务进入阻塞态
3. 外设处理完成
4. 硬件或控制器通知 CPU
5. 操作系统处理这个完成事件
6. 对应任务被改回就绪态，重新排队等待执行

所以阻塞不代表任务结束了，而是：

- 它暂时不能跑
- 等条件满足后，还会回来继续跑

## 4. 操作系统内部怎么表示进程和线程

操作系统不只是“知道有一个程序在跑”，它还要在内核里保存一大堆管理信息。

### 4.1 进程通常需要记录哪些信息

可以先分成三大类：

- **描述信息**
- **资源信息**
- **内存布局**

描述信息常见包括：

- `PID`
- 父进程 `PPID`
- 当前状态
- 优先级
- 调度相关标记

资源信息常见包括：

- 打开的文件
- 持有的内存资源
- 可能关联的设备和句柄

内存布局则描述这个进程在虚拟地址空间里的组织方式。

### 4.2 进程的内存布局

一个典型进程的地址空间里，常见会有这些区域：

- **正文段**：程序指令
- **数据段**：全局变量、常量等
- **堆**：动态分配内存的区域
- **栈**：函数调用、局部变量、返回地址等

学习阶段先记住一点就够：

**进程不是只有一段代码，它背后还要有一整套独立的内存空间。**

### 4.3 线程通常需要记录哪些信息

线程虽然比进程轻，但也不是“什么都不用记录”。

线程至少通常要有：

- `Thread ID`
- 当前状态
- 优先级
- 程序计数器 `PC`
- 寄存器现场
- 自己的执行栈

这里最重要的是：

**线程通常共享进程的地址空间，但每个线程都要有自己的执行现场。**

否则调度器切回来时，就不知道它上次执行到了哪里。

## 5. 为什么进程之间必须隔离

进程通常代表不同应用，它们需要彼此隔离。

这个隔离最核心的就是：

- **地址空间隔离**

也就是说：

- 进程 A 有自己的地址空间
- 进程 B 有自己的地址空间
- 它们默认不能随意读写对方内存

这样设计的好处很直接：

- 一个应用写坏内存，不容易把别的应用一起带崩
- 安全性更高
- 系统管理更清晰

所以进程不仅是“一个执行中的程序”，还是一个被隔离开的资源容器。

## 6. 进程和线程是怎么切换的

不管是进程切换还是线程切换，本质上都要做一件事：

- **保存旧任务的执行现场**
- **恢复新任务的执行现场**

执行现场最重要的就是：

- 程序计数器
- 通用寄存器
- 栈指针 `SP`

### 6.1 为什么要保存寄存器

因为 CPU 在执行某个任务时，当前计算状态都放在寄存器里。

如果不先保存：

- 下一个任务一运行
- 原来的寄存器值就会被覆盖
- 再切回来时，原任务就无法从正确位置继续执行

所以切换最核心的动作可以理解成：

1. 暂停当前任务
2. 保存当前任务寄存器和栈指针
3. 选择下一个任务
4. 恢复下一个任务之前保存的寄存器和栈指针
5. 让它继续执行

## 7. 为什么进程的开销比线程大

这才是这节真正要回答的问题。

先说结论：

**进程比线程重，主要重在“资源容器”和“隔离成本”，线程更多只是新增一个执行流。**

### 7.1 创建进程为什么更重

创建一个进程时，操作系统通常要做更多事情，例如：

- 创建新的进程描述信息
- 分配一套独立地址空间
- 初始化代码段、数据段、堆、栈等结构
- 复制或建立资源管理信息
- 处理父子进程关系

特别关键的是：

**进程创建往往意味着要为它准备一整套独立运行环境。**

这一步天然比“只加一个执行流”要重得多。

### 7.2 创建线程为什么更轻

创建线程时，通常不需要重新准备一整套进程资源。

它往往只需要：

- 在所属进程里新增一个线程控制信息
- 分配一个线程栈
- 设置程序计数器、寄存器初始值
- 把它加入可调度队列

也就是说，线程通常共享：

- 进程地址空间
- 打开的文件
- 大部分已有资源

所以线程创建成本通常更低。

### 7.3 进程切换为什么通常更重

线程切换和进程切换都要保存、恢复寄存器现场。  
但进程切换往往还会带来更重的额外成本：

- 需要切换到另一个进程的地址空间
- 需要处理更完整的资源边界
- 缓存和内存相关状态更容易失去局部性

而线程切换如果发生在同一个进程内部，往往只是在：

- 同一地址空间里
- 切换不同线程的寄存器和栈

所以通常会更轻一些。

### 7.4 这也是服务端常用线程而不是频繁新建进程的原因

如果一个服务每收到一个请求，都新建一个进程去处理，那么成本通常会很高：

- 创建慢
- 资源占用大
- 切换成本也高

因此更常见的思路是：

- 使用线程
- 或线程池
- 让多个执行任务共享同一个进程的资源环境

## 8. 这一节的总结

最后把这节压缩成几句话：

1. 进程是资源分配单位，线程是 CPU 调度单位
2. 操作系统通过时间片和调度器，让大量任务轮流使用 CPU
3. 进程和线程常见状态有运行、就绪、阻塞
4. 进程需要维护描述信息、资源信息和独立地址空间
5. 线程通常共享进程资源，但要有自己的栈、寄存器现场和程序计数器
6. 进程比线程更重，核心原因是进程需要独立的资源容器和隔离环境，而线程通常只是往已有进程里增加一个执行流

## 9. 一个常见问题：连续调用 3 次 `fork()`，`Hello World` 会打印几次

先看这个伪代码：

```c
fork();
fork();
fork();
printf("Hello World\n");
```

很多人第一次看会有点乱，关键是要记住：

**每执行一次 `fork()`，当前正在运行的每个进程都会再复制出一个子进程。**

也就是说，进程数会按 2 倍增长。

### 9.1 分步看这个过程

初始时只有 `1` 个进程。

执行第 `1` 次 `fork()` 后：

- 变成 `2` 个进程

执行第 `2` 次 `fork()` 后：

- 这 `2` 个进程都会各自再 fork 一次
- 于是变成 `4` 个进程

执行第 `3` 次 `fork()` 后：

- 这 `4` 个进程又都会各自再 fork 一次
- 于是变成 `8` 个进程

到执行 `printf("Hello World\n");` 时，已经有 `8` 个进程都会执行这一行。

所以最终结论是：

**`Hello World` 会被打印 `8` 次。**

### 9.2 也可以直接记公式

如果一段代码里连续执行了 `n` 次 `fork()`，并且 `printf` 写在所有 `fork()` 后面，那么最终打印次数通常就是：

```text
2^n
```

例如这里 `n = 3`，所以结果就是：

```text
2^3 = 8
```

这个题本质上考的不是输出函数，而是：

- 你是否理解 `fork()` 会复制当前进程
- 以及复制出来的子进程也会继续往下执行后续代码
