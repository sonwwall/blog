# 第十二节：用户态和内核态：用户态线程和内核态线程有什么区别？

这一节主要围绕 5 个点展开：

1. 什么是用户态和内核态
2. 系统调用是怎么从用户态进入内核态的
3. 用户级线程和内核级线程分别是什么
4. 用户级线程和内核级线程的优缺点是什么
5. 用户线程和内核线程之间常见有哪些映射模型

## 1. 什么是用户态和内核态

操作系统通常会把内存空间和执行权限分层管理。

可以先记两个概念：

- **用户空间**：主要给应用程序使用
- **内核空间**：主要给操作系统内核使用

对应到执行状态上，就是：

- **用户态**：应用程序在受限权限下运行
- **内核态**：内核在高权限下运行

### 1.1 用户态的特点

用户态程序通常：

- 不能直接访问硬件
- 不能直接执行特权指令
- 不能随意访问全部内存

这样设计的目的，是为了隔离和保护。

如果任何应用都能直接操作硬件或者任意内存，那么系统会非常不稳定，也很不安全。

### 1.2 内核态的特点

内核态程序通常：

- 可以访问更核心的系统资源
- 可以管理进程、线程和内存
- 可以和硬件设备直接交互

所以可以把它理解成：

**用户态负责“提出需求”，内核态负责“真正执行关键操作”。**

## 2. 系统调用是怎么发生的

你前面留了一个问题：

**用户态进程如果需要执行关键操作，是否也要向内核申请？**

答案是：

- 是的

用户程序如果想做下面这些事，通常都要进入内核：

- 读写文件
- 申请和释放内存
- 创建进程或线程
- 发网络请求
- 访问磁盘、网卡等设备

### 2.1 系统调用的基本过程

图片里的流程可以整理成：

1. 用户程序在用户态运行
2. 程序执行系统调用
3. 触发一次 `trap`
4. CPU 从用户态切到内核态
5. 内核执行对应的系统调用逻辑
6. 执行完成后返回用户态
7. 用户程序继续执行

这里的 `trap` 可以先理解成：

- 一种从用户态进入内核态的受控入口

也就是说，应用不是“直接闯进内核”，而是通过系统调用这个正规入口，让 CPU 帮它切换执行级别。

## 3. 线程是什么

图片里把线程叫作：

- 轻量级进程 `Light Weighted Process`

这个说法在学习阶段可以这么理解：

- 进程是资源分配的基本单位
- 线程是 CPU 调度的基本执行单位

一个进程里可以有多个线程，它们通常：

- 共享进程的地址空间
- 共享打开的文件等资源
- 但各自有自己的执行栈、寄存器上下文和程序计数器

所以线程比进程“轻”，创建和切换成本通常也更低一些。

## 4. 用户级线程和内核级线程分别是什么

这一节的核心就在这里。

### 4.1 用户级线程

用户级线程也叫：

- 用户态线程
- `User-Level Thread`

它的特点是：

- 线程信息主要维护在用户空间
- 线程的创建、销毁、切换主要由应用程序或线程库负责
- 操作系统内核不一定能直接看到这些线程的全部细节

图片里给出的结论是：

**用户态线程工作在用户空间，调度通常由进程自己负责，常见就是由进程中的主线程或线程库做二级调度。**

### 4.2 内核级线程

内核级线程也叫：

- 内核态线程
- `Kernel-Level Thread`

它的特点是：

- 线程对象由内核维护
- 线程调度由操作系统负责
- 操作系统可以直接把线程分配到不同 CPU 核心上执行

也就是说：

**内核级线程由内核直接感知、直接管理、直接调度。**

## 5. 用户级线程和内核级线程的优缺点

### 5.1 用户级线程的优点

图片里给出的优点主要有两个：

- 管理开销小
- 切换成本低

原因是：

- 很多调度动作发生在用户空间
- 不一定每次都要陷入内核
- 创建、销毁、切换通常更轻量

### 5.2 用户级线程的缺点

图片里给出的缺点包括：

- 与内核协作成本高
- 线程间协作成本高
- 无法很好利用多核优势
- 操作系统无法针对这些线程做细粒度调度优化

这里最重要的是两个点。

第一，**一个用户线程阻塞，可能拖住整个进程的执行**。

因为在很多实现里，内核看到的只是进程或者少量内核线程，看不到每个用户线程的真实状态。  
如果承载它们的那个执行实体被阻塞，那么这个进程里的其他用户线程也可能跟着受影响。

第二，**用户级线程通常不容易真正并行地跑满多核**。

尤其是在多对一模型下，多个用户线程映射到一个内核线程，本质上同一时刻还是只能由一个内核执行流承载。

### 5.3 内核级线程的优点

图片里给出的优点有：

- 可以利用多核 CPU 优势
- 操作系统级优化

这两个点很关键。

因为线程由内核直接调度，所以：

- 不同线程可以被分派到不同 CPU 核心
- 操作系统可以根据优先级、时间片、负载情况来优化调度
- 一个线程阻塞时，其他线程仍可能继续运行

### 5.4 内核级线程的缺点

图片里给出的缺点有：

- 创建成本高
- 扩展性差
- 切换成本较高

这是因为：

- 线程元数据要由内核维护
- 创建和销毁往往需要系统调用
- 线程切换通常涉及内核态参与

所以总体规律可以先记成：

- 用户级线程更轻
- 内核级线程更强

## 6. 如果一个进程下面有多个用户线程，该怎么执行

图片里提了一个问题：

如果一个用户态进程下面有多个线程，那么某个线程到底怎么被真正执行？

可以先记结论：

- 最终还是要落到某个内核线程或某个可被内核调度的执行实体上

因为真正能被 CPU 和操作系统直接调度的，归根到底还是内核能看见的执行对象。

所以可以这样理解：

- 用户线程更像“应用自己管理的一层线程抽象”
- 真正跑到 CPU 上时，还是要靠内核线程承载

## 7. 用户线程和内核线程的几种映射关系

图片里给出了 4 种常见模型：

- 多对一 `Many to One`
- 一对一 `One to One`
- 多对多 `Many to Many`
- 两层设计 `Two Level`

### 7.1 多对一

多对一的意思是：

- 多个用户线程
- 映射到一个内核线程

它的特点是：

- 用户空间调度很灵活
- 创建和切换成本低
- 但无法真正利用多核并行
- 一个阻塞可能影响整组线程

这是最典型的“轻，但问题也明显”的模型。

### 7.2 一对一

一对一的意思是：

- 一个用户线程
- 对应一个内核线程

它的特点是：

- 内核可以直接调度每个线程
- 容易利用多核
- 阻塞影响范围更小
- 但创建和切换成本更高

现代通用操作系统和很多主流语言运行时，底层更接近这种方式。

### 7.3 多对多

多对多的意思是：

- 多个用户线程
- 映射到多个内核线程

它试图兼顾两边的优势：

- 既保留用户层调度的灵活性
- 又能利用多个内核线程并行执行

不过它实现起来更复杂。

### 7.4 两层设计

两层设计可以看成多对多的一种增强版。

它的特点是：

- 大多数用户线程按多对多方式映射
- 某些重要线程也可以单独绑定到特定内核线程

这样做的目的是：

- 在灵活性和性能之间做更细的平衡

## 8. 用户态线程和内核态线程的核心区别

把前面的内容压缩一下，最适合面试回答的版本是：

### 8.1 所在空间不同

- 用户态线程主要工作在用户空间
- 内核态线程主要工作在内核空间

### 8.2 谁来管理不同

- 用户态线程主要由应用程序或线程库管理
- 内核态线程由操作系统内核管理

### 8.3 谁来调度不同

- 用户态线程调度通常是进程内部调度
- 内核态线程由操作系统统一调度

### 8.4 成本不同

- 用户态线程创建和切换成本更低
- 内核态线程创建和切换成本更高

### 8.5 并行能力不同

- 用户态线程在很多模型下不容易充分利用多核
- 内核态线程更容易真正并行执行

### 8.6 阻塞影响不同

- 用户态线程如果底层承载它的内核执行流阻塞，影响往往更大
- 内核态线程阻塞时，其他线程通常还能继续被调度

## 9. 这一节先记住的点

- 用户态是受限权限，内核态是高权限
- 用户程序访问关键资源时，通常要通过系统调用进入内核
- 系统调用一般通过 `trap` 完成用户态到内核态切换
- 用户级线程主要由用户空间线程库管理，优点是轻量，缺点是并行能力和阻塞处理较弱
- 内核级线程由操作系统管理，优点是可以利用多核并由系统直接调度，缺点是创建和切换成本更高
- 常见线程映射模型有多对一、一对一、多对多和两层设计

## 10. 一个常见补充：JVM 的线程属于哪一类

图片最后留了一个问题：

**JVM 的线程是用户态线程还是内核态线程？**

在现代主流 JVM 中，可以先记结论：

- Java 线程通常最终映射到底层操作系统的原生线程
- 所以更接近**内核级线程**

也就是说：

- Java 代码里写的是 `Thread`
- 但底层运行时通常会把它交给操作系统线程去承载

所以它一般不是传统意义上“完全由用户空间自己调度”的纯用户级线程模型。
