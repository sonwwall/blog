# 第二节：构造复杂的程序：将一个递归函数转为非递归函数的通用方法

## 1. 程序是如何被执行的

程序本身不能直接执行，先要经过编译器翻译成机器指令，然后 CPU 才能执行。

平时写的：

- 条件语句
- 循环语句
- 函数调用
- 类和对象

最后都会被翻译成更底层的指令、跳转、内存访问和栈操作。

## 2. 条件、循环、跳转的本质

### 2.1 `if-else`

`if-else` 的本质就是：

- 先做条件判断
- 再根据判断结果跳转到不同代码位置执行

所以它底层就是 `判断 + jump`

### 2.2 `switch-case`

`switch-case` 也是分支跳转，只不过它通常会做得更快一些。

常见实现方式有：

- 一连串比较后跳转
- 跳转表
- 一些额外的映射或计算

所以可以把它记成：`switch-case` 本质上也是跳转，只是比多个 `if-else` 更适合做精准匹配。

### 2.3 循环

循环控制的本质也是：

- 先判断条件
- 满足条件就跳回循环体
- 不满足条件就跳出

所以 `for`、`while` 最后也都是 `判断 + jump`

### 2.4 关于 `jump` 后面的 `nop`

不是所有 CPU 的 `jump` 后面都一定要跟一条 `nop`。

这个更多是某些架构里的实现细节，比如早期部分处理器存在延迟槽，才会看到跳转后补一条 `nop`。这个不能当成通用规律来记。

## 3. 变量、函数、类在底层是什么

### 3.1 变量

变量本质上对应一块内存空间。

可以简单记成：

- 定义变量，本质上是在申请内存
- 访问变量，本质上是在读写内存地址里的内容

### 3.2 函数

函数调用本质上就是一段代码的跳转执行。

调用一个函数时，通常会涉及：

- 传参数
- 保存返回地址
- 为局部变量分配空间
- 执行函数体
- 返回调用点继续执行

### 3.3 类和方法

类里的属性和方法，底层处理方式不同。

- 如果遇到属性，本质上是给属性分配内存空间
- 如果遇到方法，方法本身的代码放在正文段，也就是程序的代码区

调用一个类的方法，本质上还是在执行一个函数。

只是和普通函数相比，方法通常会多带一个隐含对象信息，比如 `this` 或对象地址。

## 4. 函数调用和栈

函数调用和栈是紧密相关的。

每调用一次函数，通常都会创建一个新的栈帧。

栈帧里一般会放这些内容：

- 参数
- 返回地址
- 局部变量
- 保存现场需要的寄存器值

返回值不一定总是放在栈里，很多情况下会优先通过寄存器传回。

### 4.1 普通函数在栈里的执行过程

假设有下面两个函数：

```c
int add(int a, int b) {
    int c = a + b;
    return c;
}

int main() {
    int x = add(3, 4);
    return 0;
}
```

执行过程可以记成：

1. 先执行 `main`
2. 调用 `add(3, 4)` 时，创建 `add` 的栈帧
3. 把参数、返回地址、局部变量这些信息放进栈帧
4. `add` 执行完，把结果返回
5. `add` 的栈帧弹出
6. 回到 `main` 继续执行

所以普通函数调用的特点是：

- 调用一次，压栈一次
- 返回一次，出栈一次

## 5. 递归函数在栈里的执行过程

递归函数本质上还是函数调用，只是函数调用了自己。

比如：

```c
int fact(int n) {
    if (n == 1) return 1;
    return n * fact(n - 1);
}
```

如果执行 `fact(4)`，栈的变化可以理解成：

1. `fact(4)` 入栈
2. `fact(4)` 调 `fact(3)`，`fact(3)` 入栈
3. `fact(3)` 调 `fact(2)`，`fact(2)` 入栈
4. `fact(2)` 调 `fact(1)`，`fact(1)` 入栈
5. `fact(1)` 命中递归出口，开始返回
6. `fact(1)` 出栈，结果交给 `fact(2)`
7. `fact(2)` 算完后出栈
8. `fact(3)` 算完后出栈
9. `fact(4)` 算完后出栈

这里最重要的是：

- 递归每深入一层，都会新建一个栈帧
- 返回时是从最深层开始，一层一层回退
- 这就是典型的后进先出，也就是栈

## 6. 为什么递归可以改成非递归

因为递归本质上依赖的是栈。

语言支持递归，本质上就是：

- 自动帮我们压栈
- 自动帮我们保存现场
- 自动帮我们回到上一次调用点

如果某个语言本身不支持递归，或者我们不想用系统调用栈，也可以自己维护一个栈，手动模拟这个过程。

所以递归转非递归的核心就是一句话：

`把系统帮我们做的压栈、出栈、保存现场，改成自己手动做`

## 7. 递归函数转非递归函数的通用方法

通用思路就是手写一个“调用栈”。

### 7.1 栈里要存什么

每个栈帧至少要能保存：

- 当前函数的参数
- 当前执行到哪一步
- 中间结果
- 返回后要继续做什么

也就是说，递归函数里每次调用自己时，系统替我们保存的那些信息，现在都要自己保存。

### 7.2 转换步骤

可以按下面这个顺序来记：

1. 先找出递归出口
2. 再找出递归调用前后分别做了什么
3. 设计一个栈帧结构，把参数、阶段、中间结果保存进去
4. 用显式栈替代递归调用
5. 用循环不断处理栈顶元素，直到栈空

### 7.3 最关键的一点

递归函数最难改写的地方，不是“压栈”本身，而是：

- 递归返回之后，原函数还要继续做什么

所以很多时候，栈帧里都需要一个“阶段标记”或者“程序计数器”。

## 8. 斐波那契递归改非递归的思路

题目是：

```c
int fib(int n) {
    if (n == 1 || n == 2) return n;
    return fib(n - 1) + fib(n - 2);
}
```

如果语言不支持递归，就可以自己定义一个栈帧，例如：

```c
typedef struct {
    int n;
    int stage;
    int left;
    int right;
} Frame;
```

这里：

- `n` 表示当前要求哪个值
- `stage` 表示当前函数执行到了哪一步
- `left` 表示 `fib(n - 1)` 的结果
- `right` 表示 `fib(n - 2)` 的结果

然后思路就是：

- 先把 `fib(n)` 作为第一个任务压栈
- 如果遇到出口条件，直接得到结果
- 如果还没到底，就继续把子问题压栈
- 子问题算完后，再把结果填回父问题
- 最后栈顶弹空，得到总结果

## 9. 补充

### 9.1 方法调用本质上也是函数调用

当我们调用一个 `class` 的方法时，本质上还是执行一个函数。

通常过程可以记成：

- 保存返回地址
- 传入参数
- 传入对象信息
- 跳转到方法对应的代码地址执行

所以“方法”和“函数”在底层上没有本质区别，方法可以看成“带对象上下文的函数”。

### 9.2 图灵完备

程序需要翻译成机器指令才能执行，这个翻译工具叫编译器。

如果一个语言的计算能力和图灵机等价，就说明它是图灵完备的语言。

常见编程语言大多是图灵完备的，但像 `HTML` 这种标记语言通常不是。
