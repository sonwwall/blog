# 学习笔记：红队攻击与域环境基础

今天主要学习了红队攻击的常见流程、MITRE ATT&CK 攻击矩阵、横向移动，以及 Windows 域环境里常见的一组基础概念：域控服务器、域账号、Kerberos 认证、RDP 登录和 SSH。整体上，这些内容可以放在同一条攻击链里理解：攻击者先从外部找到入口，进入内网后通过凭据、权限和网络连通性继续移动，最终接近核心资产；而域环境、远程登录协议和认证机制，正是内网攻击与防御中经常遇到的关键基础。

## 一、红队攻击的常见流程

红队攻击不是随意攻击，而是在明确授权范围内模拟真实攻击者的完整行动。它的目标不是单纯证明“能打进去”，而是验证企业在真实攻击链路下的防护、检测和响应能力。

常见流程可以概括为：

```text
授权定范围 -> 信息收集 -> 攻击面分析 -> 初始访问 -> 立足与权限维持
-> 权限提升 -> 内网侦察 -> 凭据获取 -> 横向移动 -> 达成目标
-> 清理恢复 -> 复盘报告
```

### 1. 明确目标与授权范围

红队行动开始前必须先确定规则，例如允许测试哪些系统、网段、域名和账号，是否允许社工、钓鱼、物理渗透、内网横向移动，以及出现风险时如何叫停。

红队和非法攻击最大的区别在于：红队必须有明确授权。没有授权的攻击行为，即使技术动作相似，也不属于合规红队。

### 2. 信息收集

信息收集是攻击前期最重要的环节之一。攻击者需要尽可能了解目标，包括域名、子域名、IP 段、开放端口、Web 系统、员工邮箱、组织架构、技术栈、历史漏洞和泄露凭据等。

信息收集可以分为两类：

- 被动收集：通过搜索引擎、备案信息、GitHub、社交平台、泄露库等方式收集信息，不直接接触目标系统。
- 主动探测：通过端口扫描、服务识别、目录探测等方式直接探测目标资产。

### 3. 攻击面分析与初始访问

拿到信息后，需要判断哪里最可能成为突破口。常见攻击面包括 Web 漏洞、弱口令、暴露的中间件、未修复漏洞、供应链入口和人员入口。

初始访问就是获得第一个入口，常见方式包括利用外网系统漏洞、使用泄露账号登录 VPN 或邮箱、钓鱼邮件、弱口令登录后台、攻击暴露的 Jenkins、GitLab、OA 或中间件等。

红队不一定总是依赖复杂漏洞。有时候一个弱口令、一个泄露的 Access Key、一个暴露的运维平台，就足够打开局面。

### 4. 权限提升、内网侦察与横向移动

初始入口通常权限较低，攻击者会尝试获取更多权限，寻找配置文件、密钥、脚本里的密码，或者利用错误权限配置进行权限提升。

进入内网后，会重新做一轮信息收集，例如当前机器所在网段、能访问哪些内网系统、域控在哪里、数据库和文件服务器在哪里、当前账号拥有哪些权限等。

随后攻击者会尝试横向移动，从一台机器或一个系统移动到其他机器或系统，逐步接近核心资产。

### 5. 达成目标与复盘报告

红队行动通常有预设目标，例如证明可以访问敏感数据、进入生产网、控制核心系统、获取域控权限，或者验证蓝队是否能够及时发现攻击链路。

最后输出报告时，不能只写“打进来了”，而要讲清楚：

- 为什么能打进去？
- 哪些防线失效了？
- 哪些日志没有覆盖？
- 哪些告警没有触发？
- 哪些权限设计不合理？
- 如何修复才能真正降低风险？

## 二、ATT&CK 攻击矩阵

MITRE ATT&CK 是一个用于描述真实攻击行为的知识库。它不是某个攻击工具，而是一套把攻击者行为标准化的框架。

ATT&CK 全称是：

```text
Adversarial Tactics, Techniques, and Common Knowledge
```

可以理解为“攻击者战术、技术与通用知识库”。

其中有三个核心概念：

- Tactic，战术：攻击者想达成的阶段性目的，例如初始访问、权限提升、横向移动。
- Technique，技术：实现这个目的的具体方法，例如钓鱼、利用公开漏洞、凭据转储。
- Procedure，过程：某个攻击组织、恶意软件或工具具体如何使用这项技术。

简单说：

```text
战术回答：为什么做？
技术回答：怎么做？
过程回答：具体怎么实施？
```

### 常见战术阶段

Enterprise ATT&CK Matrix 中常见战术包括：

- Reconnaissance，侦察：收集目标信息，例如域名、IP、邮箱、员工信息。
- Resource Development，资源准备：注册钓鱼域名、搭建 C2、准备恶意文件。
- Initial Access，初始访问：通过钓鱼、漏洞、泄露账号等方式进入目标环境。
- Execution，执行：让命令、脚本或恶意代码在目标系统上运行。
- Persistence，持久化：让攻击者在入口失效或系统重启后仍能回来。
- Privilege Escalation，权限提升：从低权限变成高权限。
- Defense Evasion，防御绕过：绕开安全产品、日志和告警。
- Credential Access，凭据访问：获取密码、密钥、Token、票据等认证材料。
- Discovery，发现：进入内网后探测主机、服务、账号和网络结构。
- Lateral Movement，横向移动：从一台机器移动到另一台机器。
- Collection，收集：收集文档、数据库、源码、邮件等目标数据。
- Command and Control，命令与控制：建立远程控制通道。
- Exfiltration，数据外传：把数据传出目标环境。
- Impact，影响：加密、删除、篡改数据或破坏业务可用性。

ATT&CK 的价值在于帮助安全团队把一次攻击映射成标准化链路，从而判断哪些阶段被发现了、哪些阶段没有检测能力、哪些日志缺失、哪些安全设备只是理论覆盖。

## 三、横向移动是什么

横向移动，英文是 Lateral Movement，指攻击者已经进入一个系统后，继续利用已有主机、账号、凭据或网络连通性，访问和控制同一网络里的其他主机或系统。

一句话理解：

```text
横向移动不是“怎么进来”，而是“进来之后怎么往里走”。
```

例如攻击者通过钓鱼邮件控制了一台普通员工电脑，但这台电脑本身价值有限。攻击者会继续查找这台电脑能访问哪些内网系统、有没有保存密码、能不能访问文件服务器、数据库、运维平台，最终一步步靠近核心资产。

### 横向移动依赖什么

横向移动常常依赖三类东西。

第一是凭据。攻击者会寻找明文密码、浏览器保存的密码、SSH 私钥、RDP 密码、数据库账号、VPN 账号、云平台 Access Key、Cookie 和 Token 等。一旦拿到凭据，就可以尝试登录其他机器或系统。

第二是网络连通性。不是所有机器都能访问所有系统。攻击者会判断当前机器在哪个网段、能连接哪些内网 IP、哪些端口开放、是否能访问数据库、Redis、Jenkins、GitLab、域控、文件共享或堡垒机。

第三是权限关系。比如同一个密码在多台机器复用、一个域账号可以登录多台主机、某台运维机可以 SSH 到大量服务器、CI/CD 平台可以部署生产环境、服务账号权限过大等。

### 横向移动与权限提升的区别

这两个概念容易混淆：

- 权限提升：关注同一台机器或同一系统里，权限是否从低变高。
- 横向移动：关注是否从一个系统移动到另一个系统，控制范围是否扩大。

例如普通用户变成 root 是权限提升；从员工电脑登录文件服务器是横向移动；从测试服务器跳到生产数据库也是横向移动。

## 四、域、域控服务器与域账号

Windows 企业内网中，经常会使用 Active Directory 域环境来统一管理账号、电脑、服务器和权限。

### 域是什么

域，Domain，是一种集中管理体系。它把一批电脑、服务器、用户账号和权限策略放到统一的管理范围里。

如果没有域，每台电脑都要单独管理账号，员工入职、离职、改权限都会非常混乱。使用域之后，企业可以统一创建账号、禁用账号、设置密码策略、分配用户组和访问权限。

### 域控服务器是什么

域控服务器，全称 Domain Controller，简称 DC。它是域环境里的核心服务器，负责管理整个域。

域控主要负责：

- 保存域账号信息
- 验证用户登录
- 管理用户组
- 下发组策略
- 控制谁能访问哪些资源
- 管理加入域的电脑
- 参与 Kerberos 认证

可以把域控理解成公司内网里的身份和权限中心。

如果攻击者控制了域控，通常意味着可以影响整个域里的大量账号和机器，所以域控是内网防御中的核心资产。

### 域账号是什么

域账号是由域统一管理的用户身份，例如：

```text
CORP\zhangsan
zhangsan@corp.example.com
```

它和本地账号不同。本地账号通常只存在于某一台机器上，而域账号存在于域控中，可以用于登录加入域的电脑、访问文件共享、内部系统、打印机、数据库、办公资源等。

域控和域账号的关系可以这样理解：

```text
域控：管理账号和认证的服务器
域账号：被域控管理的用户身份
```

## 五、Kerberos 认证

Kerberos 是 Windows 域环境中非常重要的认证协议。它解决的问题是：用户访问内网服务时，如何证明“我是谁”，并且不需要每访问一个服务都重新输入密码。

Kerberos 的核心思想是：

```text
不直接到处发送密码，而是通过票据证明身份。
```

### Kerberos 中的关键角色

Kerberos 简化后可以理解为几个角色：

- Client：客户端，例如员工电脑。
- KDC：密钥分发中心，通常运行在域控上。
- AS：认证服务，是 KDC 的一部分。
- TGS：票据授予服务，也是 KDC 的一部分。
- Service：用户要访问的服务，例如文件服务器、数据库或 Web 服务。

### 简化认证流程

第一步，用户用域账号登录电脑，客户端向域控证明身份。认证通过后，域控给用户一个初始票据，叫 TGT。

TGT 可以理解成：

```text
我已经通过身份验证的通行证。
```

第二步，当用户要访问某个服务，例如文件服务器时，客户端不会把密码直接发给文件服务器，而是拿 TGT 去找域控申请访问该服务的服务票据。

第三步，客户端拿服务票据访问目标服务。服务验证票据没问题后，允许用户访问。

TGT 和服务票据的区别是：

- TGT：向域控证明我已经登录过。
- Service Ticket：向具体服务证明我被允许访问你。

Kerberos 和安全关系很大，因为如果攻击者窃取了关键票据、账号密码或服务账号密钥，就可能冒充用户访问服务。

## 六、RDP 与 SSH

RDP 和 SSH 都可以用于远程连接另一台机器，但它们的定位不同。

一句话区别：

```text
RDP = 远程看桌面
SSH = 远程敲命令
```

### RDP 是什么

RDP 全称 Remote Desktop Protocol，是微软的远程桌面协议，默认端口通常是 3389。

它主要用于远程登录 Windows 图形界面。登录成功后，用户会看到远程 Windows 桌面，可以像坐在那台机器前一样操作鼠标、窗口、软件和管理工具。

RDP 常见用途包括 Windows 服务器管理、远程办公、登录跳板机、管理内网业务服务器和远程排障。

RDP 的安全风险包括暴露公网、弱口令、没有 MFA、没有限制来源 IP、允许过多域账号远程登录服务器、登录审计不足等。

### SSH 是什么

SSH 全称 Secure Shell，是一种安全远程登录协议，默认端口通常是 22。

它最常用于 Linux 或 Unix 服务器，登录后通常是命令行终端。SSH 适合执行命令、修改配置、查看日志、传输文件、做端口转发和自动化运维。

常见连接命令是：

```bash
ssh user@192.168.1.10
```

SSH 支持密码登录，也支持密钥登录。和 RDP 相比，SSH 更轻量，也更适合脚本化和自动化。

### Windows 可以使用 SSH 吗

Windows 可以使用 SSH。现代 Windows 既可以作为 SSH 客户端，也可以作为 SSH 服务端。

作为客户端时，可以在 PowerShell 或 CMD 中直接执行：

```powershell
ssh user@192.168.1.10
```

这样可以从 Windows 登录 Linux 或其他开启 SSH 服务的机器。

作为服务端时，Windows 可以安装 OpenSSH Server。安装并启动后，其他机器可以通过 SSH 登录这台 Windows 主机，进入 PowerShell、CMD 或配置好的其他 Shell。

因此，Windows 并不是只能用 RDP。是否使用 RDP 或 SSH，取决于操作需求：

- 需要图形化桌面：更适合 RDP。
- 只需要执行命令、跑脚本、查日志、传文件：更适合 SSH。

## 七、把今天的知识串起来

这些概念可以放在一条内网攻击链里理解。

假设攻击者通过钓鱼邮件控制了一台员工电脑，这是初始访问。接着攻击者在电脑上寻找浏览器保存的密码、配置文件、Token 或 SSH 私钥，这是凭据获取。然后攻击者发现这台电脑加入了 Windows 域，当前用户是一个域账号，于是开始查询域内资源、文件服务器、数据库服务器和域控位置，这是内网发现。

如果攻击者用拿到的域账号通过 RDP 登录另一台 Windows 服务器，或者用 SSH 私钥登录一台 Linux 服务器，这就是横向移动。如果攻击者进一步获取高权限账号、服务账号密钥或 Kerberos 票据，就可能扩大权限范围，甚至接近域控。

用 ATT&CK 来映射，这条链路可能对应：

- Initial Access：钓鱼邮件或漏洞利用。
- Execution：执行脚本或恶意程序。
- Credential Access：获取密码、密钥、Token 或票据。
- Discovery：枚举内网主机、账号、服务和域信息。
- Lateral Movement：通过 RDP、SSH、共享服务或远程命令执行移动到其他机器。
- Privilege Escalation：提升到管理员、root 或域高权限。
- Collection / Exfiltration：收集并外传目标数据。

## 八、容易混淆的点

### 1. 域控不是普通服务器

域控虽然也是服务器，但它的关键性远高于普通业务服务器。它管理身份、认证和权限策略。如果域控被控制，整个域的安全边界都会受到严重影响。

### 2. 域账号不是本地账号

本地账号只存在于某台机器上，域账号由域控统一管理，可以跨多台加入域的机器和服务使用。域账号泄露后，风险通常比单机本地账号更大。

### 3. 横向移动不等于权限提升

权限提升强调权限变高，横向移动强调访问范围扩大。实际攻击中，两者常常交替出现：先移动到一台机器，再在这台机器上提权，再继续移动。

### 4. RDP 和 SSH 都是远程访问方式，但体验不同

RDP 偏图形界面，SSH 偏命令行。RDP 常用于 Windows 桌面和服务器管理，SSH 常用于 Linux 服务器和自动化运维。Windows 也可以使用 SSH，Linux 也可以通过额外组件支持远程桌面。

### 5. Kerberos 的重点是票据

理解 Kerberos 时，不要只记名词。它最核心的思想是：用户通过域控认证后，使用票据访问具体服务，避免密码在网络中反复传输。

## 九、实践与防御建议

从防御视角看，今天这些知识对应的安全建设重点包括：

- 对外暴露资产要持续梳理，减少不必要的公网入口。
- VPN、RDP、SSH、后台系统等入口要启用强认证和 MFA。
- 域账号权限要遵循最小权限原则，避免普通账号拥有过多访问能力。
- 高权限账号不要在普通终端上随意登录，减少凭据被窃取的机会。
- 生产网、办公网、测试网、数据库区、管理区要做网络隔离。
- 禁止密码复用，尤其是本地管理员密码、服务账号密码和运维账号密码。
- 配置文件、脚本、文档和代码仓库中不要保存明文密码或长期有效密钥。
- 监控异常登录、内网扫描、远程命令执行、短时间访问多台主机等行为。
- 重点保护域控，限制访问来源，开启审计，监控高危操作。
- 对 ATT&CK 矩阵中的关键技术建立检测覆盖，定期用红队或攻防演练验证是否有效。

## 十、今日总结

今天学习的核心可以总结为一句话：

```text
红队攻击关注完整攻击链；ATT&CK 用标准化方式描述攻击链；
横向移动描述攻击者进入内网后的扩展过程；
域控、域账号、Kerberos、RDP 和 SSH 是理解 Windows 企业内网攻防的重要基础。
```

如果用于面试复习，需要重点掌握：

- 红队攻击的一般流程是什么。
- ATT&CK 中 Tactic、Technique、Procedure 的区别。
- 横向移动是什么，和权限提升有什么区别。
- 域控服务器的作用是什么。
- 域账号和本地账号有什么区别。
- Kerberos 为什么使用票据认证。
